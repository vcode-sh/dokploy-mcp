## Verified compatibility issue (blocking)

**Verified on March 25, 2026 against the current Dokploy instance:**

- `GET /api/project.all` returns `200`
- `GET /api/trpc/project.all` returns `200`
- `GET /api/project.one?projectId=...` returns `200`
- `GET /api/trpc/project.one?projectId=...` returns `400`
- `GET /api/trpc/project.one?input={"json":{"projectId":"..."}}` returns `200`

**Conclusion:** the current bug is not the `/api/trpc` prefix by itself. The real compatibility issue for this repository is that the client correctly normalizes to `/api/trpc`, but still serializes parameterized `GET` requests as flat query parameters instead of the tRPC `input={"json":...}` envelope.
